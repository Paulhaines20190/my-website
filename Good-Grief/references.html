API and accessibility checks

Checks recorded on 20 October 2026. These checks support development; they are not a claim of WCAG conformance.

Verified automatically

  • Simulated DOM checks: shared navigation and Escape handling; correct tab state and focus with and without jQuery; character-dialog focus return after saving a favourite.
  • Form checks: empty book-search input is rejected before a network request; advice errors identify the affected field; the quiz explains unanswered questions and hides Back on its first question.
  • Mock API checks: the submitted keyword appears in the request URL; page navigation, work descriptions, no matches, malformed responses, retry and an unavailable biography provider are handled.
  • Live server-side requests: Open Library search and Wikipedia’s Charles M. Schulz summary each returned HTTP 200. This does not verify browser CORS or every catalogue result.

Still to verify manually

  • Chrome, Safari and Firefox at phone, tablet and desktop widths; 200% and 400% zoom; both themes and all focus indicators.
  • Keyboard-only use, native dialog focus containment and Escape, and announcements with VoiceOver or NVDA.
  • Browser API requests, offline behaviour and a complete contrast/accessibility audit. Automated DOM checks do not test visual layout or screen-reader output.
